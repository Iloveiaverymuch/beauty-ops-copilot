# ADR-002: Native ADK Evaluation Framework and Vertex AI Gen AI Evaluation Service

Status: accepted · Date: 2026-11-11 · Evidence: `evals/FINDINGS.md` (R5 entry), `evals/adk/README.md`, `evals/vertex/README.md`

Each decision: context → decision → alternatives rejected → evidence → consequences / when to revisit.

---

## 1. Migration from Promptfoo to ADK Native Evaluation (`google.adk.evaluation`)
- **Context.** Promptfoo required a separate Node.js / npm runtime (`npx promptfoo`, `node --test`), a background FastAPI server, HTTP network serialization, and external JavaScript assertions (`check.cjs`). This fragmented our Python-first environment (ADK 2.13, uv, pytest) and created dual-toolchain CI overhead.
- **Decision.** Replace Promptfoo with ADK's built-in evaluation framework (`google.adk.evaluation`), using `beauty_advisor.evalset.json` (7 benchmark cases), `test_config.json`, and deterministic Python evaluators (`evals/adk/custom_evaluators.py`).
- **Rejected.**
  - Keeping Promptfoo with Node.js in GitHub Actions (slows CI, requires maintaining JavaScript and Python assertions simultaneously).
  - Pure black-box HTTP testing without agent state access (hides intermediate tool calls and agent reasoning state).
- **Evidence.**
  - Offline runner (`InMemoryRunner`) executes all 7 cases in <1s with 0 cloud cost.
  - Pytest regression suite (`tests/test_adk_eval.py`, 14 tests) ensures evaluator correctness.
  - Eliminated `actions/setup-node`, `node --test`, background uvicorn servers, and all `npx` downloads from CI workflows.
- **Consequences.** The evaluation suite runs natively inside the Python environment with full access to ADK session events, tool call payloads, and intermediate agent traces.

## 2. Vertex AI Gen AI Evaluation Service for Cloud Benchmarking and LLM-as-a-Judge
- **Context.** Deterministic rules (canaries, regex, JSON schema) verify basic safety and tool compliance, but cannot evaluate semantic dimensions like answer groundedness, persona tone/empathy, or refusal nuance at scale.
- **Decision.** Implement Vertex AI Gen AI Evaluation Service (`vertexai.evaluation.EvalTask`) with 4 Pointwise 1–5 rubrics:
  1. `groundedness_score`: faithfulness to retrieved tool context.
  2. `persona_quality_score`: conversational beauty advisor style (Léa), warm tone, proactive advice.
  3. `safety_refusal_score`: principled refusal without canary or prompt leakage.
  4. `claim_compliance_score`: accurate return policy and claim status without unauthorized promises.
  Track benchmark runs in Vertex AI Experiments (`beauty-advisor-benchmark`).
- **Rejected.**
  - Third-party SaaS evaluators (Langfuse, Braintrust, Weights & Biases) that would introduce external API keys and data egress outside Google Cloud.
  - Ad-hoc custom LLM judging scripts without standardized schema or experiment tracking.
- **Evidence.** Live evaluation in GitHub Actions scored 5.0/5.0 across all 4 rubrics using `gemini-3.8-flash` via Vertex AI in `eu`.
- **Consequences.** Benchmarks and production trace evaluations are centralized directly in Vertex AI Experiments and BigQuery without additional SaaS dependencies.

## 3. Two-Tier CI/CD Strategy: Fast Offline Gate vs On-Demand Live Cloud Evaluation
- **Context.** Live LLM evaluations incur cloud billing costs, rate limits, and network latency variance (10–30s per run), making them unsuitable for mandatory PR-blocking gates on every commit.
- **Decision.** Establish two distinct evaluation tiers in GitHub Actions (`.github/workflows/ci.yml`):
  1. **Automatic CI Gate (PR / push to master)**: Runs `uv run pytest` (106 unit tests) and `uv run python -m evals.adk.run_adk_eval --offline` using deterministic fixtures. Zero network, zero GCP credentials, finishes in ~21 seconds. Required by GitHub branch protection.
  2. **Manual Live Cloud Evaluation (`workflow_dispatch`)**: Runs `run_adk_eval.py --live` against live Gemini 3.8 Flash, Discovery Engine ranking, and mock retail APIs, followed by `run_vertex_eval.py` for LLM-as-a-judge scoring and experiment tracking. Authenticates via Google Cloud Service Account key (`GCP_SA_KEY`).
- **Rejected.**
  - Running live model evaluations on every PR (expensive, flakiness on quota/tail latency).
  - Completely manual local-only evaluation (risks untested regressions slipping into master).
- **Evidence.**
  - Intentional regression branch `test/eval-gate-regression` leaked off-topic facts; GitHub Actions CI Gate failed in 21s and branch protection blocked PR merging.
  - Live workflow ran on GitHub Actions: 7/7 PASSED + LLM Judge 5.0/5.0.
- **Consequences.** Developers get sub-30-second deterministic feedback on every push, while live model quality is verifiable on-demand before releases.

## 4. Discovery Engine Ranking API IAM and Regional Alignment
- **Context.** The hybrid retrieval architecture (`advisor/retrieval/modes.py`) performs cross-encoder reranking using Discovery Engine's ranking API (`discoveryengine.googleapis.com/.../default_ranking_config:rank`). During live evaluation in CI, calls failed with HTTP 403 Forbidden.
- **Decision.** Grant `roles/discoveryengine.editor` to the CI service account (`github-evals-runner@rk-adk-poc-1104.iam.gserviceaccount.com`). Align regional routing: Vertex AI MetadataStore falls back to `europe-west1` when running in `eu`, while model inference operates on `eu` multi-region.
- **Evidence.** Post IAM propagation, live evaluation went from 5/7 passed (2 HTTP 403 errors on KB ranking) to 7/7 passed.
- **Consequences.** All GCP service accounts executing retrieval evaluations must hold both `roles/aiplatform.user` and `roles/discoveryengine.editor`.
